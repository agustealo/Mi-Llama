# Product media and screenshot contract

Mi-Llama documentation distinguishes **brand artwork** from **product evidence**.

## Brand artwork

Brand artwork is repository-owned and may be used in README files, docs, release notes, manifests, package pages, and repository/social metadata. Canonical assets live in `docs/assets/`.

## Product screenshots

A screenshot is evidence of a real runnable product surface. Generated UI, composited mockups, or aspirational screens are not substitutes.

The consumer workspace shell is now a real Mi-Llama surface attached to the FastAPI application. The canonical gallery is captured from the exact same HTML, CSS, and JavaScript committed under `src/mi_llama/workspace_assets/`.

The committed PNG gallery is generated by the repository's Product Gallery workflow. Documentation-only commits may follow a capture without invalidating it; any change to workspace source or workspace assets requires a fresh capture.

## Required gallery

At least these six captures must remain present under `docs/assets/screenshots/`:

1. `01-overview.png` — project overview, workflow, and runtime authority state.
2. `02-library.png` — Research Library source-ingestion surface.
3. `03-research.png` — evidence/question review workspace.
4. `04-notebook.png` — notebook and research-structure workspace.
5. `05-manuscript.png` — outline/manuscript writing surface and research margin.
6. `06-intelligence.png` — evidence-aware writing-intelligence review surface.

Additional captures may document provider/model selection, collaboration, onboarding, or other shipped surfaces later.

## Capture rules

Every committed screenshot must:

- come from the actual Mi-Llama workspace source committed at the same revision or its unchanged workspace parent;
- contain no API keys, bearer tokens, private source documents, email addresses, or other secrets;
- prefer empty or neutral product state over invented user records when a live authenticated dataset is not available;
- have no developer-tool overlays unless documenting a developer surface;
- be captured at 1440×960 unless a later gallery contract intentionally changes the viewport;
- use stable semantic filenames rather than dates, random hashes, or external image hosts;
- be refreshed when the visible product materially changes.

## Capture procedure

The screenshots are produced from the running `mi-llama` FastAPI application. The capture task starts the app with non-secret documentation-only configuration, opens each hash route (`#overview`, `#library`, `#research`, `#notebook`, `#manuscript`, `#intelligence`) in Chromium at 1440×960, and captures the page without post-compositing.

## README policy

The README should show the brand banner and a concise real-product gallery. Deeper documentation may show the complete six-screen set. Any image that no longer matches the running shell must be refreshed or removed.
